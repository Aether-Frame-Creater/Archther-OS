# Hyprland Implementation Record — Modular Configuration

Implemented against Hyprland **0.56.2-4** (Lua config API), live session
verified at runtime. Design source: `docs/HYPRLAND-ARCHITECTURE.md`.

## Repository configuration tree

```text
config/hypr/
├── hyprland.lua            # entry point: warning line + 7 ordered requires
└── modules/
    ├── variables.lua       # mainMod, terminal, fileManager, menu command
    ├── environment.lua     # XCURSOR_SIZE / HYPRCURSOR_SIZE
    ├── monitors.lua        # permissive monitor defaults
    ├── settings.lua        # general, layouts, decoration, misc, input,
    │                       # gesture, example device stanza
    ├── animations.lua      # bezier/spring curves + animation assignments
    ├── window-rules.lua    # 3 active window rules
    └── keybindings.lua     # all binds + Wofi launcher fix
```

Deferred with rationale: `workspaces` (only commented examples exist),
`autostart` (block fully commented; daemons run via systemd user units),
`themes/*` (Phase 2 / 04). No empty modules were created.

## Module-loading pattern chosen

Plain `require()` calls in the entry point, in dependency order — the pattern
the official 0.56 wiki endorses. No custom loader (no demonstrated need).

- `variables.lua` is pure data (returns a table, no `hl.*` calls); consumers
  load it via their own `require()` (Lua caches the table after first load),
  so no `local` state is shared across module boundaries.
- Verified from Hyprland upstream source (`src/config/lua/ConfigManager.cpp`):
  the config directory is prepended to Lua `package.path`, so dot-notation
  requires (`require("modules.variables")`) resolve under `~/.config/hypr/`.
  A missing module is a fatal config error; an error *inside* an existing
  module is recorded without stopping the other modules. Every required file
  was confirmed present before activation.

## Migration from the stock configuration

Source of truth was the live `hyprland.lua` (364 lines), read in full — not
memory, not the upstream example. Two corrections to the Task 003 plan
resulted: `environment.lua` **was** created (live `hl.env` lines exist), and
animation values were taken from disk, never upstream.

- Preserved verbatim: monitor defaults, all `hl.config` values, curves,
  animations, gesture, the example device stanza (flagged as unmatched
  hardware), all window rules, all binds, the autogenerated warning line.
- Intentionally dropped (zero behaviour): commented-out upstream examples
  (autostart, workspace rules, permissions, layer rule) referencing software
  that is not installed here. The pre-migration backup retains the original.
- The static cross-check caught and fixed three transcription slips before
  deployment (an arithmetic typo, two upstream-vs-disk value confusions, one
  added style flag). Method below.

## Wofi binding change (the one authorized behaviour fix)

- Before: `SUPER+R` → `menu` = `hyprlauncher` (not installed; bind dead).
- After: `SUPER+R` → `/usr/bin/wofi --show drun` (Wofi v1.5.3 verified
  installed; `drun` launches `.desktop` entries per the installed `wofi.7`
  man page). Binding key unchanged; no other shortcut touched.
- Reported, not changed: 6 binds reference missing helpers —
  `brightnessctl` (2 binds) and `playerctl` (4 binds) are not installed.
  `hyprshutdown` is also absent but that bind falls back to `hyprctl`.

- Binds: 48 before → 48 after (loop expansion matches exactly); all 10

- A physical `SUPER+R` keypress was deliberately **not** exercised from this

  would be intrusive). Manual test for the owner: press `SUPER+R`, type an
  app name, launch it, confirm focus.
- Audible volume/brightness/media-key behaviour untested (helpers partly
  missing — see above); multi-monitor behaviour untested (single eDP-1
  observed); workspace/session flows unchanged by construction.

## Safe instructions for future configuration updates

1. Edit only under `config/hypr/`; keep one concern per module.
2. `luac -p` every touched file; re-run the API-multiset/diff cross-check
   for value migrations.
3. Take a fresh timestamped backup of `~/.config/hypr/` (outside the repo).
4. Copy `modules/` first, byte-compare, then swap `hyprland.lua` atomically;
   never symlink the live dir to the working tree.
5. `hyprctl reload`, then verify: `configerrors` empty, bind count stable
   across two reloads, monitors unchanged.
6. On any failure: stop, preserve the failed tree aside, restore the backup,
   compare, and report — per `docs/RECOVERY-GUIDE.md`.
