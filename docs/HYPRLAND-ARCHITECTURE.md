## 2. Proposed directory tree (future `config/hypr/`)

```text
config/hypr/
├── hyprland.lua            # entry point: ordered require() list only
└── modules/
    ├── variables.lua       # mainMod, terminal, fileManager, menu command
    ├── monitors.lua        # monitor defaults
    ├── settings.lua        # general, input, decoration, layout, misc
    ├── animations.lua      # curves + animation assignments
    ├── window-rules.lua    # window rules (workspace rules later, if needed)
    └── keybindings.lua     # all keyboard shortcuts incl. launcher fix
```

Deliberately **not** created now: `modules/environment.lua` (no `hl.env`
lines exist locally), `modules/workspaces.lua` (only commented examples
locally), `modules/autostart.lua` (block fully commented out; daemons already
come from systemd user units — see §6), `themes/archther.lua` (deferred to
Phase 2 / 04). No empty directories or placeholder files were added by this
task.

## 3. Module responsibilities and dependency order

Load order in `hyprland.lua` (each module `require()`d exactly once, top to
bottom):

| # | Module | Responsibility | Source in stock config | Needed for initial migration? |
|---|---|---|---|---|
| 1 | `variables.lua` | Shared constants: `mainMod`, app commands. Single place the launcher fix lands | “MY PROGRAMS” block (~lines 38–42) | Yes — every later module consumes these |
| 2 | `monitors.lua` | Output/mode/position/scale defaults; no machine-specific names | “MONITORS” block (~line 26) | Yes — keep permissive defaults |
| 3 | `settings.lua` | `general`, `input`, `decoration`, `dwindle`/`master` layout flags, `misc` | `hl.config` blocks (~lines 95–260) | Yes — core behaviour |
| 4 | `animations.lua` | Bezier/spring curves + `hl.animation` assignments | Curves/animations block (~lines 138–213) | Yes — sizable, theme-adjacent; isolation keeps future theme work clean |
| 5 | `window-rules.lua` | `suppress-maximize-events`, XWayland drag fix, `hyprland-run` rule | Window-rules block (~lines 300–364) | Yes — preserves existing behaviour verbatim |
| 6 | `keybindings.lua` | All `hl.bind` calls; workspace loops; media keys; **Wofi launcher fix** | Binds block (~lines 264–296+) | Yes — user-facing behaviour lives here |

Dependency rule: modules consume `variables.lua` and never each other;
`hyprland.lua` contains no settings itself, only the ordered requires plus a
comment header. Deferred modules (`environment`, `workspaces`, `autostart`,
`themes/*`) slot into this order later without renumbering existing ones.

## 4. Verified Lua module-loading behaviour

Sources: version-pinned **Hyprland 0.56 wiki “Start Here”**
(`https://wiki.hypr.land/0.56.0/Configuring/Start/`, fetched 2026-10-10),
upstream `example/hyprland.lua` (same date), and the stock config’s own
`require("myColors")` comment.

- **Verified:** splitting via `require()` is the officially endorsed pattern
  (“You can (and should!!) split this configuration into multiple files”).
- **Verified:** Hyprland executes each `require()`d file in a **separate Lua
  scope**, so an error in one file does **not** stop the others from loading.
- **Verified:** that protection does **not** cover module resolution — a
  `require()` of a **missing** module throws and **kills** the config load.
  Every required file must exist before activation.
- **Unverified:** the exact base `require()` resolves relative to (config dir
  vs. other). This must be tested in-session during implementation (see §8):
  stage the tree, keep entry + `modules/` co-located, activate, and confirm
  all six modules load; if resolution differs, adjust the require paths —
  never the live config — until proven.
- **Side-effect discipline (proposal):** `hl.bind`/`hl.config` calls apply at
  require time, so require each module exactly once, never inside loops, and
  keep modules free of cross-requires. Reload idempotency of `hl.bind`
  (replace vs. duplicate) is **unverified** — the implementation task must
  reload twice and confirm via `hyprctl binds` that no duplicates accumulate.

## 5. Wofi launcher migration plan

1. **Verified:** Wofi `v1.5.3` installed at `/usr/bin/wofi`; `--show` selects
   the mode; `drun` launches `.desktop` entries (installed `wofi.7`).
2. **Proposed command:** `wofi --show drun` — desktop-entry launcher, no new
   dependencies, consistent with the Wofi-first architecture decision.
3. **Binding:** preserve `SUPER+R`; no conflict or usability issue found in
   the stock binds (workspace keys use numbers, no `R` collision).
4. **Later test procedure (implementation task):** from a live session, press
   `SUPER+R`, type a known app prefix, launch it, confirm focus + exit code;
   also test with zero matches (must show empty, not hang) and test
   `wofi --show run` as the documented fallback if `.desktop` lookup fails.
5. **If Wofi is missing or fails:** the bind must surface a visible failure
   (e.g. notify via `dunstify`/terminal message), never silently do nothing;
   the install-phase fallback is reinstalling `wofi` from official repos —
   not adopting another launcher without review.

## 8. Validation and rollback strategy (for the implementation task)

1. Take a **fresh timestamped backup** of `~/.config/hypr/` (same method as
   `docs/BASELINE-AUDIT.md` §G) before any migration step.
2. Build the modular tree in a **staging directory first**, never in
   `~/.config/hypr/`.
3. Syntax-check every file with `luac -p` (catches syntax errors; cannot
   catch `hl.*` API misuse — say so in the report).
4. Deploy by preserving the live dir aside (`hypr.<stamp>`), copying the
   staged tree in, and `diff -r`ing against the stage source.
5. Activate **from inside a live Hyprland session**: reload, confirm all six
   modules loaded (missing module = fatal load, per §4), exercise every
   bind group, reload a second time and check for duplicate binds.
6. Roll back by restoring the fresh backup per `docs/RECOVERY-GUIDE.md`; the
   guide stays accurate because rollback still means “one directory restore”.
7. Report: `luac` results, reload behaviour, bind verification, and anything
   that required a second attempt.
